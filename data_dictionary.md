# Data Dictionary: Logistics Data Quality Dataset

This document explains the fields generated by the synthetic data script (`generate_manifests.py`) and outlines the rules that distinguish clean data from injected data quality errors.

## Dataset Fields

| Field Name | Data Type | Description | Example (Clean) | Clean Data Rule | Possible Dirty Error |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `manifest_id` | String | Unique identifier for the shipping manifest document. | `MAN-49182375` | Must be globally unique and follow "MAN-[8 digits]". | `duplicated_manifest_id`: ID appears more than once. |
| `shipment_id` | String | Unique identifier for the specific shipment. | `SHP-12849502` | Must be globally unique. | - |
| `container_id` | String | Standardized container alphanumeric ID. | `ABCD 1234567` | Follows 4 letters, space, 7 digits format. | - |
| `shipment_date` | Date (ISO) | Date the shipment was dispatched. | `2023-11-15` | Must be a date in the past. | `future_shipment_date`: Date is > today. |
| `origin_country` | String | ISO 2-letter country code of departure. | `CN` | Must be a valid known ISO code. | `invalid_country`: Unrecognized code like "ZZ". |
| `destination_country` | String | ISO 2-letter country code of arrival. | `CA` | Must be a valid known ISO code, different from origin. | - |
| `origin_port` | String | Name of the departure port. | `Port of Shanghai` | Port must physically exist in `origin_country`. | `port_country_mismatch`: e.g., Port of Rotterdam in origin CN. |
| `destination_port` | String | Name of the arrival port. | `Port of Vancouver` | Port must physically exist in `destination_country`. | - |
| `carrier_name` | String | Name of the shipping line/carrier. | `Maersk Shipping` | Non-empty string. | - |
| `importer_name` | String | Company receiving the goods. | `Acme Corp` | Non-empty string. | - |
| `exporter_name` | String | Company sending the goods. | `Global Supply Ltd` | Non-empty string. | - |
| `product_description` | String | Free-text description of the goods. | `Premium electronics - microchips` | Non-empty string detailing a product. | `missing_product_description`: Field is empty/null. |
| `hs_code` | String | Harmonized System customs code (8 digits). | `85421100` | 8 numerical digits; must logically match `product_description`. | `invalid_hs_code_format` (letters used), `hs_code_product_mismatch` (Code for horses assigned to electronics), `missing_hs_code`. |
| `declared_weight_kg` | Float | Total weight of the shipment in kg. | `1500.50` | Must be > 0 and physically plausible for the product type. | `negative_weight` (< 0), `unrealistic_weight` (e.g., 15005000.00 for small goods). |
| `declared_value_usd` | Float | Total declared value for customs in USD. | `75000.00` | Must be > 0; ratio of value/weight should align with product category. | `extreme_declared_value`, `suspicious_low_value_high_weight` (e.g., $1.00 for 5000 kg). |
| `quantity` | Integer | Number of discrete units in the shipment. | `450` | Must be > 0. | `quantity_zero` (0 units declared). |
| `unit` | String | Unit of measure for the shipment. | `kg` | Standardized unit. | - |
| `currency` | String | Currency of the declared value. | `USD` | Standard ISO currency code (baseline is USD). | `currency_mismatch` (e.g., EUR used but value is calculated in USD). |
| `transport_mode` | String | Method of transportation. | `Ocean` | One of: Ocean, Air, Rail, Truck. | - |
| `risk_category` | String | Baseline risk tier assigned by business rules based on value/type. | `low`, `medium`, `high` | Defined by deterministic rules (e.g., Value > $1M is high). | - |
| `expected_review_status` | String | The desired outcome for this row in the final dashboard workflow. | `Auto Approve` | Clean rows should be auto-approved; high risk or dirty rows should require review. | Corrupted rows correctly flag as `Manual Review`. |

## Error Log Output
The script generates an `error_log.csv` which tracks every single injection. 
- `manifest_id` / `shipment_id`: The affected record.
- `error_type`: The category of the injected error.
- `affected_field`: The column that was changed.
- `original_value`: What the valid data was.
- `corrupted_value`: The dirty data now in the dataset.
- `severity`: low, medium, high, critical.
- `detection_hint`: The type of model or rule needed to catch this (e.g., "Anomaly detection", "NLP description to HS code mismatch").
